# CV page — visual web version, sober PDF, one content source

## Intent
The web CV page should be more visual; the PDF must stay sober. Content is not changing —
only presentation. Web and PDF must never drift apart.

## Goals / non-goals
- Goal: a web page that reads at a glance (key figures, timeline, chips, cards).
- Goal: the PDF looks as it does today.
- Goal: content written once.
- Non-goal: new content, rewording.
- Anti-goal: two hand-maintained copies of the CV.

## Approaches considered
1. **Single YAML source + MkDocs hook rendering two pages** — chosen. Consistency by construction.
2. Two Markdown files + a CI diff check — rejected: every edit twice, fuzzy comparison.
3. (Earlier) one Markdown file with web-only blocks hidden in print — dropped in favour of
   separate pages with a shared source.

## Design
- `data/cv.yml`: all CV content (header, summary, experience, projects, basins, publications,
  skills, education, languages, contact). Paragraphs are Markdown strings. Outside `docs/` so it
  is not published as a raw file.
- `hooks/cv.py` (MkDocs built-in `hooks:`, no new dependency; PyYAML ships with MkDocs):
  on `cv.md` and `cv-print.md`, replaces a marker with content rendered from the YAML —
  rich HTML for the web page, the current plain Markdown layout for the print page.
- `docs/cv.md`: front matter + marker. Web layout:
  - header with title, summary and **Download PDF** button;
  - **key-figure tiles** (15 years · 20+ basins · 5 continents · 8 publications), listed in the YAML;
  - **experience as a vertical timeline** (years on the rail, role, organisation badge; nested
    project highlights and software contributions as sub-items);
  - **selected projects as link cards**;
  - **basins**: core areas as cards, "also worked" as chips grouped by region;
  - **publications** with year/venue badge;
  - **skills as chips grouped by domain**;
  - education/certifications as compact cards; languages with a level indicator.
  - Uses the site's existing colour tokens; works in light/dark; single column on phones.
- `docs/cv-print.md`: front matter + marker, `search: exclude`, kept out of the nav
  (`not_in_nav`). Renders today's structure so the PDF is unchanged.
- CI: Chrome prints `site/cv-print/index.html` instead of `site/cv/index.html`.
- CSS in `extra.css`, `?v=` bumped.

## Verification
- `mkdocs build` passes.
- Text of the new print page matches the current CV text (diff of extracted text).
- Web page checked in light, dark and phone widths; PDF rendered locally and compared.

## Left to the builder
Exact visual styling of tiles, timeline and chips, within the site's existing look.
A world map of basins is not included (needs a base map and coordinates); can be added later.
